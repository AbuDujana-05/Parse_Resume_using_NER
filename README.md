# Parse Resume using NER

Custom spaCy v3 statistical NER + OpenCV OCR/layout + FastAPI + React/Vite.

## Included proof artifacts
- `backend/datasets/processed/`: annotated data shipped with the supplied project and the exact processed train/dev JSON used by the verified run.
- `backend/data/train.spacy` and `backend/data/dev.spacy`: spaCy DocBin binary training artifacts.
- `backend/output/`: loss chart, confusion matrix, and training metrics generated by the training script.
- `backend/models/ner_model/`: serialized custom spaCy NER pipeline.
- `backend/datasets/raw/`: public dataset source/provenance records plus the reproducible downloader.

## Local Windows / PowerShell
From the project root:

```powershell
npm install
npm run dev
```

`npm run dev` now launches `START_LOCAL.ps1`. The launcher checks the Python dependencies, clears stale listeners on ports 8000/5173, starts FastAPI, waits for `/api/health` with the spaCy model loaded, and then opens Vite in a separate PowerShell window. Netlify is not involved in this local path.

Backend-only commands:

```powershell
cd backend
python -m pip install -r requirements.txt
python prepare_data.py
python train_antigravity.py
python app.py
```

## Netlify deployment
The root `netlify.toml` builds directly from the single project root. Netlify therefore installs from `package-lock.json`, runs `npm ci && npm run build`, and publishes `dist`.

The project also contains a same-origin Netlify Function at `netlify/functions/api.mjs`. It proxies `/api/*` to the real FastAPI backend. Set this Netlify environment variable for live parsing:

`BACKEND_URL=https://YOUR-PUBLIC-FASTAPI-BACKEND`

You may alternatively set `VITE_API_BASE_URL` to the same public FastAPI origin; in that case the browser calls that backend directly.

The proof dashboard does not depend on the backend: training metrics and charts are bundled under `public/proof/`.

### Netlify upload-size protection
Netlify buffered function requests are limited to 6 MB, with binary uploads effectively lower after base64 encoding. The frontend limits production uploads to 4 MB and the FastAPI backend enforces the same ceiling for the Netlify path.

## Public dataset provenance
The public sources referenced by the downloader include Dotin's 545 annotated-resume dataset (CC0-1.0) and the DataTurks annotated resume dataset. Dotin documents 545 resumes with 12 entity categories and says the dataset contains fake names/emails for anonymization. The downloader records exact source URLs and downloaded-file metadata when run.

The verified bundled model was trained from the data shipped with the supplied project because this execution environment could not retrieve the public binary archives. No external records are claimed as part of that verified run. Running `python download_public_datasets.py` on a normal Windows machine with internet access downloads the public source files into `backend/datasets/raw/`, after which `prepare_data.py` can ingest supported JSON/JSONL sources and regenerate the DocBins.


## Local run (separate from Netlify)
Run `npm run dev` (recommended). It starts both services automatically. You can still run the backend manually with `cd backend; python app.py`, or the frontend only with `npm run dev:frontend`. The browser uses the backend on port 8000 automatically when running on localhost/port 5173.


### Local API wiring
When the app is opened on localhost/127.0.0.1 or Vite port 5173, `src/api.js` targets the backend on port 8000 using the current browser hostname. This avoids a missing-backend fetch caused by accidentally starting only the Vite frontend. Local development does not depend on a Vite `/api` proxy or Netlify routing.
